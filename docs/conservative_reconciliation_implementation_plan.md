# Conservative Evidence Reconciliation Implementation Plan

## Status

**`IMPLEMENTATION_NOT_STARTED`**

**`TRAINING_NOT_STARTED`**

**`EXTERNAL77_NOT_ACCESSED`**

Plan date: 2026-09-08

Governing protocol: `docs/conservative_reconciliation_protocol.md`.

Formal method: **Conservative Evidence Reconciliation (CER)**. Its sole
primary mechanism is the **Context-Corroborated Evidence Gate (CCEG)**.

The implementation must preserve the protocol's three scope actions exactly:
`DIRECT` is protected with `KEEP`, `LOCAL_CONFLICT` receives the explicit
E1-compatible `DELETE`, and `NON_EVIDENCED` uses the CCEG
`KEEP`/`DELETE`/`ABSTAIN` rule. `ABSTAIN` leaves the original pair unchanged.

This document specifies a future implementation only. It creates no source
module or runner, trains no model, recalibrates no score, selects no threshold,
evaluates no Legacy121 performance, and opens no external77 path. Frozen
R2/R3/R4 artifacts remain read-only.

## 1. Planned implementation surface

The future execution task should add only the following minimal components:

- `src/rna_ccfa/conservative_reconciliation.py`: CCEG score/action semantics,
  paired branch contracts, scope precedence, action accounting, and
  `CONSERVATIVE_DEV_GATE` evaluation;
- `scripts/audit_conservative_reconciliation_protocol.py`: protocol/input hash,
  forbidden-path, split-role, R4-asset, and non-execution preflight;
- `scripts/build_conservative_reconciliation_development_views.py`: immutable
  references/views over the existing R4 feature and clean-evidence artifacts;
- `scripts/train_conservative_reconciliation_development.py`: complete paired
  condition x branch x channel x fold x seed development matrix;
- `scripts/calibrate_and_lock_conservative_reconciliation.py`: validation-only
  branch calibration, corroborated-risk construction, threshold selection, and
  seals;
- `scripts/evaluate_conservative_reconciliation_development.py`: one locked
  development-assessment pass and complete KEEP/DELETE/ABSTAIN accounting;
- `scripts/summarize_conservative_reconciliation_development.py`: reliability,
  utility, scope, evidence-attribution, source, comparator, and development-gate
  summaries.

No external77 runner is planned in this execution stage. external77 remains a
locked `ONE_SHOT_INDEPENDENT_TEST`. A future external runner may be designed
only after `CONSERVATIVE_DEV_GATE_PASS_DEVELOPMENT_ONLY` and a separate
final-policy seal.

Each planned command must provide audit/dry-run behavior and fail before
scientific work on any protocol/hash/path mismatch. The implementation must not
silently reinterpret an R4 helper whose semantics differ from CER.

No CER artifact may be written inside a frozen R2/R3/R4 result directory. The

```text
PREFLIGHT_PASS
-> FEATURE_REFERENCE_LOCKED
-> SPLITS_LOCKED
-> TRAINING_COMPLETE
-> CALIBRATION_COMPLETE
-> THRESHOLDS_SEALED

```

An invalid or incomplete state cannot be skipped or repaired by deleting a
failed run.

## 4. Feature artifact schema

CER should not duplicate the large R4 feature tables. It should create:

```text
features/
  feature_contract_reference.json
  candidate_row_inventory.parquet
  positive_pair_item_inventory.parquet
  unpaired_item_inventory.parquet
```

`feature_contract_reference.json` records:

- governing CER protocol hash and implementation commit;
- exact R4 feature-contract path/hash;
- ordered 80 candidate, 17 positive-pair item, 8 unpaired item, and four
  descriptor names/dtypes;
- explicit zero-evidence transform;
- permitted model columns and forbidden metadata/label columns;
- source-identity exclusion;
- statement that no feature was added, removed, reordered, refit globally, or
  selected from R4 postmortem strata.

The inventory tables retain immutable row/item IDs and source artifact hashes,
but model loaders expose only the frozen numerical columns. Labels, GT status,
true evaluation scope, source, density, evidence seed, and result metadata
remain outside the model tensor. Operational scope is computed at action time
from delivered items; it is not a newly learned feature.

Every referenced R4 row must appear exactly once in the appropriate inventory.
Expected counts are 310,838 candidate realizations, 3,523 positive-pair
manifests, 3,630 unpaired manifests, 7,153 combined manifests, 121 RNAs, and
363 source records.

## 5. Development split manifest

Create one immutable split record per channel and rotation:

```text
splits/<channel>/rotation_<k>.json
```

Each record contains:

- grouped-fold source path/hash;
- exact RNA IDs for `development_train`, `development_validation`, and
  `development_assessment`;
- candidate/manifest/item row counts and hashes for each role;
- proof that roles are pairwise RNA-disjoint;
- proof that every source record and evidence realization for an RNA follows
  the RNA role;
- explicit `independent_test=false` for all Legacy121 roles;
- no path or identifier from external77.

Rotation remains assessment fold `k`, validation fold `(k+1) mod 5`, and the
other three training folds. The implementation must reject historical aliases
such as `held_out_test` in CER output schemas because they obscure the changed
scientific role.

## 6. Model and matched-control schema

The run key is:

```text
condition x branch x channel x rotation x model_seed
```

Allowed values are:

```text
condition: CER | CER_EVIDENCE_MASKED
branch: EVIDENCE_BRANCH | CONTEXT_BRANCH
channel: positive_pair | unpaired
rotation: 0 | 1 | 2 | 3 | 4
model_seed: 17 | 29 | 41 | 53 | 67
```

Expected nominal runs: `2 x 2 x 2 x 5 x 5 = 200`.
The canonical five model seeds are `17, 29, 41, 53, 67`; every seed is retained.

Run directories:

```text
runs/<condition>/<branch>/<channel>/rotation_<k>/seed_<s>/
  run_config.json
  preprocessing.json
  training_history.csv
  validation_logits.parquet
  checkpoint.pt
  checkpoint_provenance.json
  completion.json
```

Every run records architecture, parameter count, evidence-mask state,
initialization/batch seed, optimizer/loss settings, train/validation RNA and
row IDs, package/device/determinism settings, chosen epoch and tie trace, all
parent hashes, command, exit state, and checkpoint hash.

The pairing audit must prove identical candidates, labels, splits,
architecture, nominal capacity, seeds, optimizer, batches, and checkpoint rule.
For `CER`, only EVIDENCE_BRANCH receives usable evidence. For the control, both
branches receive exact zero evidence. CONTEXT_BRANCH is masked in both
conditions. The two fully masked control branches are still materialized and
audited; deterministic equality is expected when all inputs/seeds are equal.

Checkpoint files remain outside Git unless the repository's artifact policy
explicitly permits them. Durable provenance must include their hashes and
storage locations.

## 7. Calibration and CCEG threshold artifacts

Per branch, write:

```text
calibration/<condition>/<branch>/<channel>/rotation_<k>/seed_<s>.json
```

The artifact stores monotone Platt `a,b`, convergence, class counts, validation
log loss before/after, fit role, checkpoint/logit hashes, and explicit denial
of development-assessment and external77 label access.

After both branch calibrators are sealed, build validation-only CCEG rows with
`q_E`, `q_C`, and `r_CCEG=min(q_E,q_C)`. Fit the protocol's monotone policy
calibrator on `logit(clip(r_CCEG,1e-7,1-1e-7))`, require a strictly positive
slope, and emit calibrated `q_CCEG`. This final monotone step preserves the
conjunctive order while giving Brier/ECE a calibrated probability target.
Write:

```text
thresholds/<condition>/<channel>/rotation_<k>/seed_<s>/
  validation_cceg_scores.parquet
  policy_calibration.json
  validation_risk_curve.parquet
  locked_threshold.json
  lock_seal.json
```

The threshold artifact records every unique-score tie block, delete-none,
dual event/RNA preservation eligibility, ordered tie-break trace, selected
numeric threshold and its inverse raw corroboration cutoff, or a fail-closed
reason, resulting KEEP/DELETE/ABSTAIN counts, and hashes of all parents. It must
explicitly state `r4_threshold_reused=false`.

The seal must exist and match before any development-assessment feature or
label row can be loaded by evaluation code.

## 8. Development-assessment and result schemas

Pair-score rows should contain:

- immutable candidate, manifest, RNA, channel, rotation, and model-seed IDs;
- condition and both branch IDs/checkpoint/calibrator hashes;
- raw logits, calibrated `q_E`/`q_C`, raw `r_CCEG`, and calibrated `q_CCEG`;
- locked threshold and operational scope;
- KEEP/DELETE/ABSTAIN decision and immutable original-pair membership;
- evaluation-only label, true scope, source, density, evidence seed, and full
  parent provenance.

Write rows to:

```text
pair_scores/<condition>/<channel>/rotation_<k>/seed_<s>.parquet
evaluation/<condition>/<channel>/rotation_<k>/seed_<s>.json
```

The evaluator must prove deletion-only subset invariants and complete TP/FP/FN
plus action/scope accounting. It must not expose assessment results until every
required checkpoint, calibrator, threshold, and seal across the 200-run matrix
is complete.

Primary combined Track E tables concatenate positive-pair and unpaired rows for
the same condition/seed across rotations. They are not a third model, channel
ensemble, or channel-selection opportunity.

## 11. Leakage and forbidden-path guards

The future implementation must fail closed on:

1. any RNA overlap between development roles;
2. any source/evidence realization of one RNA crossing roles;
3. preprocessing, class weighting, fitting, checkpoint selection, calibration,
   or threshold selection using development-assessment data;
4. any external77 or future independent-test path access;
5. any noisy/real-evidence or historical E2 execution path;
6. any feature outside the exact R4 allowlist;
7. predictor/source identity, GT-derived inference data, R4 decision/risk, B2
   disagreement, postmortem bin, density, or evidence seed entering a tensor;
8. any nonzero evidence proxy in a masked branch;
9. any architecture/capacity/optimizer/split/batch mismatch in a paired control;
10. R4 threshold/calibrator/checkpoint reuse as a CER fitted artifact;
11. source- or density-specific threshold, seed/channel selection, dropped run,
    or alternate primary gate;
12. pair addition, partner reassignment, decoder/refolding output, incomplete
    edit accounting, or nondeterministic repeated inference.

## 12. Planned unit, toy, and consistency tests

Before full Legacy121 development training, implement tests for:

- exact R4 80/17/8/4 feature-contract reference and feature parity;
- no new tensor column and complete metadata/label firewall;
- DIRECT protection, LOCAL_CONFLICT deletion, and exhaustive scope precedence;
- CCEG `min` score and KEEP/DELETE/ABSTAIN truth table, including equality;
- ABSTAIN leaves the original pair unchanged and cannot drop a denominator;
- evidence/context branch architecture and parameter-count equality;
- exact evidence-zero behavior for every masked item/mask/descriptor/proxy;
- complete 200-run key matrix and five-seed no-selection handling;
- grouped RNA development roles and forbidden `held_out_test` naming;
- train-only preprocessing/class weights and validation-only checkpoints;
- separate monotone branch calibration with missing-class fail closed;
- monotone CCEG policy calibration, strict-positive slope, inverse cutoff, and
  calibrated-probability reliability semantics;
- unique-score tie blocks, delete-none, dual 0.99 validation eligibility, and
  exact tie-breaks;
- assessment-label access denial before the complete threshold seal;
- deletion-only pair-set and full action/scope edit accounting;
- AUPRC, AUROC, Brier, ECE, utility, RNA-balanced, and source aggregation;
- evidence-attributable FP gain/TP harm and R4-gain-retention formulas;
- every `CONSERVATIVE_DEV_GATE` strict/non-strict boundary;
- frozen B0/E1/P3/R4/B4/B2 join and no comparator rewrite;
- external77/noisy/real/historical-E2 forbidden-path guards;
- deterministic repeated inference and byte-stable summarization;
- documentation-state agreement for protocol frozen/not executed.

A tiny synthetic end-to-end fixture may test code mechanics. It must not read
Legacy121, produce a scientific metric, choose a protocol variant, or count as
CER execution.
